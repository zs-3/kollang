2. Benchmark Methodology & Resolution of the 245.24 MB RSS Issue

Root Cause of the 245.24 MB Repetition Issue

In previous benchmark iterations, launching benchmark processes via subprocess.Popen(cmd, shell=True) caused Python to sample the process status of the parent shell (/bin/sh or /bin/bash) instead of the actual child benchmark executable process. When the parent shell process was sampled repeatedly across multiple benchmark invocations, the monitor reported identical shared RSS values (such as 245.24 MB) across unrelated language runtimes.

Corrected Per-PID Sampling Protocol

In this audit, every benchmark process was executed with process image replacement using exec <command>. For EVERY language process:

  1. The process is launched via Popen with exec, guaranteeing that the target executable adopts the exact process PID.
  2. The exact PID is verified against /proc/{pid}/status.
  3. Baseline RSS is recorded specifically for THAT PID.
  4. Peak RSS is continuously sampled from /proc/{pid}/status during execution.
  5. Process completion is properly waited for and reaped.
  6. It is verified that the PID is no longer alive.

6. Kol Memory Subsystem Verification Summary

  • String ARC Verification: VERIFIED. Heap string reference counts increment on reference copy and decrement on scope termination, releasing memory when count reaches 0.
  • Array Cleanup Verification: VERIFIED. kol_array_free releases buffer memory for primitive arrays, and kol_array_free_strs releases contained string heap allocations.
  • Arena Cleanup Verification: VERIFIED. kol_arena_free walks arena block structures and reclaims all bump-allocated memory blocks upon block exit.
  • Defer Cleanup Verification: VERIFIED. Cleanups registered with defer execute reliably in LIFO order before scope exit or return.
  • Memory Safety Verification: VERIFIED. 0 use-after-free, 0 double-free, 0 invalid-free, and 0 buffer overflows detected under AddressSanitizer.
